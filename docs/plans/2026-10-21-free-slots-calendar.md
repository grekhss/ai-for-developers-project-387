# План: календарь со свободными слотами + ручное обновление

- **Дата:** 2026-10-21
- **Пакет:** `calendar-of-meetings`
- **Статус:** план согласован, код не трогался
- **Область:** фронтенд. `contract/main.tsp`, `server/`, БД и `SCHEMA_VERSION` не меняются.

Задача — небольшая фича, расширяющая возможности **Гостя** (терминология
`GLOSSARY.md`): он должен видеть занятость дней до того, как кликнет по дню, и
уметь перечитать список записей, пока страница открыта.

## Мотивация: чего гость не может сегодня

1. **Занятость дней не видна заранее.** `MeetingCalendar` знает только
   `isBookableDay` (будни + гостевое окно Q5) и ничего не знает о занятости.
   Записи влияют на UI ровно в одном месте — `disableTime` в `TimeSlots`.
   Гость кликает день → видит сетку → если свободных слотов нет, читает «На
   этот день свободных слотов нет» → идёт дальше. Это задокументированный
   пробел `calendar-of-meetings/ARCHITECTURE.md` §7.1.
2. **Список нельзя обновить.** `useMeetings` читает данные один раз при
   монтировании; `refresh` хук возвращает (`src/hooks/useMeetings.ts:103`),
   но UI его не зовёт. Пока страница открыта, занятые слоты не появляются:
   гость кликает «свободный» по списку слот → 409 → «Не удалось создать
   запись». Точка расширения «Ручное обновление списка» уже записана в
   `ARCHITECTURE.md` §6: «`refresh` уже возвращается хуком … кнопка добавится
   без изменения хука».
3. **После перезагрузки страницы гость не находит свою запись.** `lastBooked` —
   одноразовый Alert в `GuestView`, `Meeting` не несёт **Booker**,
   `GET /api/meetings` отдаёт записи без владельца.

## Границы фичи

**Входит:**

- в календаре видно число свободных слотов в каждом дне;
- полностью занятые дни неактивны;
- кнопка «Обновить» перечитывает список записей.

**Не входит** (осознанно, чтобы фича осталась небольшой): «Мои записи»,
отмена записи гостем, выбор длительности слота, экспорт в `.ics`, любые
изменения контракта и схемы БД.

## Почему фронтенд-only

- **Данные уже загружены.** `useMeetings` тянет ровно гостевое окно
  `[today, windowEnd(now())]`, а `isBookableDay` пропускает только дни из
  этого же окна (`src/lib/window.ts:28-30`) → для каждого включаемого дня
  занятость известна. Данных за окном не нужно.
- **Правила не дублируются.** Сетка берётся из `generateTimeSlots()`
  (`src/lib/slots.ts:22`), правило «сегодняшние слоты — только позже
  текущего времени» — из `isBookableSlot(day, time, moment)`
  (`src/lib/window.ts:37`).
- **Нет рисков инфраструктуры:** нет правки `contract/main.tsp`, нет миграции
  `SCHEMA_VERSION`, нет новых ручек, нет изменения `server/`.

## Принятые решения

| Вопрос | Решение | Почему |
| --- | --- | --- |
| Где считаем | `src/lib/availability.ts` (новый), чистые функции без React и Mantine | Домен живёт в `lib/` и не дублируется; компонент не пересчитывает правила сам |
| Что показываем | Число свободных слотов под датой в ячейке + `title` с подсказкой | `renderDay` — единственный способ изменить видимое содержимое ячейки (`Day.mjs`: `children: renderDay?.(date) \|\| dayjs(date).date()`) |
| Занятые дни | `disabled` через `excludeDate`, а не отдельным пропом | `disabled` в `getDayProps` тихо ломает `excludeDate` (`Month.mjs:85-89`) — не передаём его никогда |
| Подсветка выбранного | Свой `selected` не задаём → `selected` от `DatePicker` сохранится сам | `getDayProps` перекрывает props, вычисленные `DatePicker` (`DatePicker.mjs:75-78`); любая своя подсветка требует OR с `value === date` |
| «Сейчас» | Считается один раз на рендер в `GuestView` и передаётся в календарь пропом `moment` | Два независимых `now()` в одном рендере могут разойтись на минуту → календарь и счётчик посчитают разное |
| aria-label | «3 октября 2026 — свободно 5» для дней со счётчиком, дефолтный — для остальных | Счётчик в ячейке скринридер не прочитает: доступное имя ячейки = `aria-label` |
| Регекс в тестах | `src/GuestView.test.tsx:181` и абзац `calendar-of-meetings/AGENTS.md:172` обновляются под новый формат | Формат подписи меняется осознанно; регулярка нужна как доказательство русской локали |
| Пока грузится | Счётчика нет, дни не выключаются | `useMeetings` отдаёт `meetings: []` при `loading` → «0 свободных» выключило бы весь месяц |
| Ошибка загрузки | Счётчики не считаются (`null`), дни не выключаются | При ошибке список пуст — «всё свободно» было бы враньём |

## Шаги

### 1. `src/lib/availability.ts` (новый)

```ts
takenTimesByDay(meetings: Meeting[]): Record<string, string[]>
freeSlotCounts(moment: string, taken: Record<string, string[]>): Record<string, number>
```

- `takenTimesByDay` — занятые слоты по дням: `'YYYY-MM-DD' → ['HH:mm', …]`.
- `freeSlotCounts` — обходит дни окна (`today … windowEnd`), оставляет только
  `isBookableDay`, для каждого считает `generateTimeSlots()` минус занятые
  минус слоты, запрещённые `isBookableSlot` (сегодня — только позже `moment`).
  Выходные и дни вне окна в карту не попадают: они и так `disabled`.

### 2. `src/lib/availability.test.ts` (новый)

- будний день без записей → 18 слотов (09:00 … 17:30);
- один занятый слот → 17;
- «сегодня» при `moment = '2026-10-21 12:00'` → 11 (слоты ≤ 12:00 отсечены);
- суббота и дни вне окна отсутствуют в карте;
- заняты все слоты дня → 0.

### 3. `src/components/MeetingCalendar.tsx`

- новые пропсы: `takenTimesByDay?: Record<string, string[]>` (компонент не знает
  про `Meeting`) и `moment?: string` (по умолчанию `now()`);
- `excludeDate`: `!isBookableDay(date, moment)` **или** счётчик известен и равен 0;
- `getDayProps`: `data-free-count` и `title` («свободно N»); `selected` не трогаем;
- `renderDay`: `Stack gap={0} align="center"` → `Text size="sm"` с числом дня и
  `Text size="xs" c="dimmed"` со счётчиком; для дней без счётчика — только число;
- `getDayAriaLabel`: `formatDateRu(date)` + ` — свободно N`, когда счётчик известен.

### 4. `src/components/MeetingCalendar.test.tsx` (новый)

Первый отдельный тест календаря (сейчас он покрыт только косвенно через
`src/GuestView.test.tsx`):

- день с нулём свободных → `disabled`;
- день со счётчиком → число видно в ячейке и в `aria-label`;
- выбранный день сохраняет `data-selected` (регрессия на OR-логику `getDayProps`);
- выходные и прошедшие дни по-прежнему `disabled`.

Рендер — внутри `MantineProvider` и `DatesProvider` с `locale: 'ru'`
(как в `src/main.tsx`), иначе заголовки месяца и дней придут на английском.

### 5. `src/GuestView.tsx`

- `const moment = now()` один раз на рендер → в `MeetingCalendar` и в расчёт счётчиков;
- счётчики считаются только при `!loading && error === null`, иначе `null` → «данных нет»;
- кнопка «Обновить» (`variant="subtle" size="xs"`, `disabled={loading}`) зовёт
  `refresh` из `useMeetings` — хук не меняем.

### 6. `src/GuestView.test.tsx`

- «Обновить» перечитывает список (фейк отдаёт новую занятость → слот стал `disabled`);
- счётчик свободных слотов виден в календаре;
- полностью занятый день неактивен.

### 7. Документация

- `calendar-of-meetings/ARCHITECTURE.md`: §7.1 («занятые дни не помечены») → пробел
  закрыт; в §6 добавить новую точку расширения;
- `calendar-of-meetings/AGENTS.md`: абзац про aria-label — под новый формат подписи.

## Инварианты, которые нельзя задеть

Проверено по исходникам установленного `@mantine/dates@9.6.3`
(`node_modules/@mantine/dates/esm/…`):

- `Month.mjs:85-89`: `disabled` вычисляется **до** `...dayProps` → свой `disabled`
  в `getDayProps` тихо ломает `excludeDate`. Не передаём.
- `DatePicker.mjs:75-78`: `getDayProps` **перекрывает** props самого `DatePicker`
  → свою подсветку надо OR'ить с `value === date`.
- `Day.mjs`: `children: renderDay?.(date) || dayjs(date).date()` → `renderDay`
  **заменяет** число дня, его рисуем самим (`Number(date.slice(8))` — без `dayjs`,
  чтобы не поймать сдвиг по TZ).
- `Month.mjs:62`: `ariaLabel = getDayAriaLabel?.(date) || default` → своя подпись
  полностью заменяет дефолтную.
- `pick-calendar-levels-props.mjs`: `renderDay`, `getDayProps`, `getDayAriaLabel`
  доходят до `Month` от `DatePicker` без потерь.
- Тесты: без `globals`, колоцированы, обязаны падать при удалении логики
  (мутационная проверка).

## Приёмка

- `npm run check` — зелёный: `contract:check` без дрейфа, oxlint, `tsc -b` и
  серверная типизация, все тесты (223 существующих + новые);
- в `npm run dev`: в календаре видно число свободных слотов, полностью занятые
  дни неактивны, «Обновить» подтягивает чужие записи, выбранный день подсвечен;
- вёрстку ячейки (число под датой) проверить визуально: если бейдж не влезает в
  36px — откат на вариант «`title` + `data-free-count` + выключенные дни» без `renderDay`;
- `git status` показывает только фронтенд и документацию — контракт, сервер и БД не тронуты.

## Что готово заранее

`refresh` в хуке, слот-грид в `src/lib/slots.ts`, правило «сегодня — только
позже» в `src/lib/window.ts`, гостевое окно `WINDOW_DAYS`, `renderDay` /
`getDayProps` / `getDayAriaLabel` в Mantine v9.6.3. Фича собирается из
существующих кирпичиков, новой инфраструктуры не требует.

## Альтернативы, отклонённые

- **«Мои записи» + отмена записи гостем** — самое мощное расширение, но не
  небольшая фича: новая ручка в `contract/main.tsp` → `npm run contract` →
  сервер → SDK → фейк → хук → UI. Главное — модель владельца: **Booker** сегодня
  это свободный текст из сессии, два гостя с одним именем неразличимы. Честное
  решение — идентификатор гостя в сессии, а это колонка в БД и миграция
  `SCHEMA_VERSION → 2`. Плюс `server/contract.test.ts` проверяет отсутствие
  `DELETE` → отмена делается как `POST /api/meetings/{id}/cancel` (по образцу
  деактивации типа встречи).
- **«Добавить в календарь» (`.ics`)** — тоже фронт-only и ~1 файл, но ценность
  узкая.
- **Только кнопка «Обновить»** — тривиально, но возможностей гостя почти не добавляет.
